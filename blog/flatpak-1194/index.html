Flatpak 1.19.4: what actually changed

Flatpak 1.19.4

A beta development prerelease with two security fixes, COSMIC applet desktop keys, and new search filters. It also absorbs the withdrawn 1.19.3 tag, so this is the first usable release of that batch.

Flatpak 1.19.4 shipped on November 24 as a beta development prerelease from the 1.19.x branch. No feature freeze date has been announced. Flatpak publishes odd-numbered series as a rolling set of point releases, and the maintainers state that the first stable release from this branch will be 1.20.0, with stable OS releases staying on 1.18.x until then. This tag also absorbs the work from 1.19.3, whose release process failed, so the notes cover everything accumulated since 1.19.2.

The headline is security. Two advisories went out with this tag: a critical local privilege escalation in the system helper and a full sandbox escape through the portal. Alongside those are command line and sandbox fixes plus desktop integration work for COSMIC. What is still open is the 1.20.0 stable tag and the stable-series backports that distributions will pick up on their own schedule.

Things worth your attention

Two security fixes in the system helper and portal

CVE-2026-133842 is rated critical. If an app, runtime or extension installed system-wide uses the extra-data mechanism and its apply_extra program creates a deeply nested directory hierarchy, Flatpak can leave a setuid-root executable under /var/lib/flatpak with its setuid bit intact. A malicious local user working with such an app can turn that into root privilege escalation. The fix makes permission canonicalization fail closed when it cannot open a directory (Flatpak commit d087606) or when readdir() fails (Flatpak commit a21a102). Reported by RoyalOughtness, fixed by Simon McVittie. By default only root-equivalent users can install apps system-wide, which limits exposure, but any setup that relaxes the polkit rules for Flatpak is at risk.

CVE-2026-133845 is rated high and affects anyone running a malicious or compromised Flatpak app. If the third argument to the portal’s Spawn() call maps two file descriptors to the same handle, dup2() fails. That failure was not handled, so a descriptor open inside flatpak-portal ended up in the subsandbox. Predicting the number of the unfiltered D-Bus session bus descriptor is enough to escape the sandbox completely. The immediate mitigation exits the child process when fd mapping fails (Flatpak commit f107d8a). The thorough fix adds a FlatpakUniqueFDList so one descriptor cannot be used twice (Flatpak commit b1b596e, Flatpak commit a7b55f8, with Flatpak commit 07b007e renaming the old variables). Reported by refi64 and independently rediscovered by oz9un, with fixes from refi64 and Simon McVittie.

Both are fixed in the stable 1.18.6 release as well. The advisories note that the 1.19.3 and 1.18.5 tags contained the fixes but their release process failed, so 1.19.4 and 1.18.6 are the tags to use. Backports exist on the flatpak-1.16.x branch for distributions such as Debian 13, though upstream will not publish a formal release from it.

The command line loses a flag and gains search filters

flatpak update --force-remove is gone (Flatpak issue 6915). It had no effect, so the only visible change is that scripts still passing it now get an error. That is the incompatible command line change in this release.

flatpak search gains --app and --runtime (Flatpak issue 6718, implemented in Flatpak issue 6902), matching filters flatpak list already had. So flatpak search --app game looks only at applications, and flatpak search --runtime org.gnome limits results to runtimes. Searches with many matches are faster too (Flatpak issue 6892).

COSMIC applets can export their desktop keys

PR Flatpak PR 6865 adds five COSMIC keys to the allowlist Flatpak applies to exported .desktop files. Without this, those fields were stripped from sandboxed apps. The keys and what they do:

  • X-CosmicApplet marks an applet for the settings app and the panel.
  • X-CosmicHoverPopup asks for a popup on hover when another applet already has one open.
  • X-CosmicOverflowPriority sets the priority of an applet in panel overflow behavior.
  • X-CosmicOverflowMinSize sets the minimum size of a shrinkable applet in applet size units.
  • X-CosmicShrinkable marks a window whose panel padding can shrink so it takes less space.

Who it affects: COSMIC users and anyone packaging a COSMIC applet as a Flatpak. The pull request carried a needs-backport label, and the stable-series backport was still open as Flatpak issue 6936 at release time.

Fonts and sandbox restrictions

Both ~/.local/share/fonts and the legacy ~/.fonts are available inside the sandbox when both exist (Flatpak issue 5675, Flatpak issue 6869). Previously an app could not see font files placed in the older path. Apps started with --no-session-bus or --no-a11y-bus now pass the same restriction to the subsandboxes they create (Flatpak issue 6968), closing a gap where a child sandbox regained bus access its parent had given up.

Smaller changes

Performance and internals

  • Time-remaining estimates during install are more accurate (Flatpak issue 6732).
  • Truncated and dropped HTTP downloads are retried (Flatpak issue 6881), so a flaky connection is less likely to fail an install.
  • flatpak enter picks the smallest process ID when matching by name (Flatpak issue 6878), which is more likely to be the main instance.
  • flatpak uninstall --unused avoids removing pinned runtimes and extensions (Flatpak issue 6859).
  • GPU-rendered terminal emulators no longer flicker (Flatpak issue 6959).

Visual polish and output

  • App IDs are no longer ellipsized by default (Flatpak issue 4719), and AppStream summaries fold onto one line (Flatpak issue 6132), which makes long output easier to read.
  • Agreement titles are no longer shown as though they were the app’s name (Flatpak issue 6965).

Developer tools and documentation

  • Command line completion is improved (Flatpak issue 6759) and faster (Flatpak issue 6325).
  • API documentation received a round of fixes (Flatpak issue 6890, Flatpak issue 6914, Flatpak issue 6912, Flatpak issue 6963).
  • flatpak override precedence is documented (Flatpak issue 6478), as is flatpak build --readonly (Flatpak issue 6966) and how to clear a remote subset filter (Flatpak issue 5637).

Translations

Translation updates shipped for pl, pt_BR, sl and zh_CN.

Bug fixes

Sandbox and portal

  • OCI repositories no longer report up-to-date refs as having updates available (Flatpak issue 6874).
  • The missing SpawnStarted signal from the portal when SPAWN_NOTIFY is used is restored (Flatpak issue 6864).
  • GIO warnings while accessing the system repository are gone (Flatpak issue 6413, Flatpak issue 6766).
  • Unusual WAYLAND_DISPLAY values are handled (Flatpak issue 6970).
  • flatpak install --or-update and --reinstall are no longer ignored when used with .flatpakref files (Flatpak issue 5460).
  • Propagation of the gpg-verify option is fixed so a .flatpakrepo file can disable GPG verification (Flatpak issue 6934).
  • Trailing slashes in --persist paths are ignored, so the persistent directory mounts where intended (Flatpak issue 1469).
  • flatpak-coredumpctl returns early if the selected process is not a Flatpak app (Flatpak issue 6975).

Command line and remotes

  • flatpak remote-ls works with a non-default --arch (Flatpak issue 3805).
  • An assertion failure in flatpak remote-info when optional metadata is missing is fixed (Flatpak issue 6945).
  • flatpak search no longer crashes on AppStream components with no name (Flatpak issue 6958).
  • flatpak run no longer crashes when the GPG agent socket cannot be found (Flatpak issue 6969).
  • Apps missing from native sideload repository listings are back (Flatpak issue 6939).
  • flatpak update --no-pull no longer pulls updated AppStream metadata (Flatpak issue 5163).
  • The default branch for an app in a specific installation is no longer affected by the default branch in another installation, and a runtime shell uses the copy from the selected installation (Flatpak issue 6917).

Libraries and build

  • Memory leak fixes (Flatpak issue 6863, Flatpak issue 6930).
  • Some tests now pass when bubblewrap is unavailable, and a test race condition is removed (Flatpak issue 6963).
  • Test coverage and internal test infrastructure improved (Flatpak issue 6931, Flatpak issue 6932, Flatpak issue 6938, Flatpak issue 6919, Flatpak issue 6980).

Still in flight

Flatpak publishes the 1.19 series as rolling development prereleases and has not announced a feature freeze date, so there is no formal list of proposed features waiting for a later 1.19.x tag. Everything in the 1.19.4 notes is merged and published; there is no hidden batch of finished work behind this tag. Two things are genuinely still open. The first stable release from this branch, 1.20.0, has not been tagged. The COSMIC desktop key change carries a needs-backport label, and its stable-series backport was still open in Flatpak issue 6936, so 1.18.x users will not get it in 1.18.6. Anything else that lands before 1.20.0 will arrive in a later point release, and I would not assume any particular feature will make it.

Known regressions and deferred work

None listed yet. The 1.19.3 tag carried the same fixes but its release process failed, so anyone who picked up that tag directly should move to 1.19.4. The advisory for CVE-2026-133842 notes that exploit attempts can leave behind a directory under /var/lib/flatpak/app/ containing a setuid executable. After the fix the files/extra subdirectory is locked down so non-root users cannot reach it, but that leftover directory is not cleaned up. Debian 13 users on the 1.16.x branch get backports of both fixes but no formal upstream release.
