Cinnamon 6.8.4: what actually changed

Cinnamon 6.8.4

A small stable point release from November 20 that fixes modal dialogs closing too early, workspace switches that never finished, and a lock screen that showed the default avatar. It also brings a round of translation regeneration.

Cinnamon 6.8.4 is a stable point release, tagged and published on November 20, 2026. There is no feature freeze to talk about here: the 6.8.0 feature work landed on November 4, and 6.8.1 through 6.8.4 are a run of small fix releases inside two weeks. The GitHub release entry carries no notes text, so the authoritative record is the Debian changelog and the tagged diff. This covers all five code changes in 6.8.4.

Things worth your attention

Modal dialogs no longer close on a held modifier

If you opened the run dialog, Expo or the overview with a Super based shortcut, releasing Super closed the modal straight away. The dialog only stayed open while you held the key, which made combos like Super+space useless inside it. The fix came from a reported issue and landed in that fix.

The stage event handler now records a modifier as “tapped” only when it was pressed while the modal was up and no other key was pressed before its release. A click, touch or scroll cancels the tap. A modifier you were already holding when the modal opened, such as the one from the shortcut that launched it, is never recorded, so letting go of it does nothing. The same tap test is used by the run dialog, Expo and the workspace view when they decide whether to close. This also feeds modifier only keybindings, so a bare Super press can be bound without it firing on the release of a shortcut. Keyboard users and anyone relying on Super based launchers are the ones who notice.

Workspace switches finish when a window closes mid slide

Dániel Ruszki fixed a stuck workspace animation in a reported issue, closing an older report. If you closed a window while the switch slide was running, Cinnamon never called completed_switch_workspace(). Muffin kept switch_workspace_in_progress at 1, and while it was non zero it skipped plugin effects and deferred hiding windows. From that point every minimized window stayed painted on screen until the next workspace switch or a Cinnamon restart.

The two slide animations now use onStopped instead of onComplete, so an interrupted transition still removes its actor from the pending sets. Actors are removed before cleanup, which makes re entry through remove_all_transitions() harmless, and a complete() helper disconnects the kill handler and calls completed_switch_workspace() exactly once. The author reproduced it on X11 with animations on, and reported the minimize behaviour back to normal at 0, 50 and 100 ms delays. This matters most on X11 sessions with animations enabled.

Smaller changes

Visual polish

The lock screen no longer draws your picture when it is the default avatar. If you never set an account photo, the generic silhouette is now hidden instead of shown on the unlock dialog, while a real photo still appears as before. The user widget is re centered each time the screensaver runs, because the widget is kept around rather than rebuilt and has to react to an avatar change. The same hiding rule was applied to the menu applet and the user applet popup menu, but not the panel icon.

Under the hood the unlock dialog gets a hideDefaultImage flag, and the avatar widget uses it to decide whether the image is visible. The screen shield wraps the dialog in a bin layout container and centers that container within the monitor space, taking the on screen keyboard height into account.

Developer tools and localization

The translation generation script had a path bug. generate_cs_module_desktop_files.py imported config.py straight from the source tree even though that file is now a configured one, so it read the wrong copy. It now uses the installed file. Running the generation scripts refreshed roughly 36 .desktop files, which is why a five commit release touches 48 files with close to a thousand added lines.

The visible result is new translated names, comments and search keywords. The virtual keyboard gains names such as “Teclado virtual” in Galician, “Виртуалды пернетақта” in Kazakh and “Виртуал гар” in Mongolian, plus matching translated keywords. The screenshot app’s desktop file picked up the largest batch, around 175 new lines of translated names and comments, so “Take a Screenshot of an Area” now has translations in many more languages. Accessibility settings gained keywords like “лупа;сөйлеу;қол жеткізу” in Kazakh. This is translation content only, with no change to how the apps behave.

Bug fixes

Compositor, display and input

The modifier tap work also fixes Expo and the overview closing when you release Super after using a Super based shortcut. Both now call isModifierTap() before hiding themselves. Clicks, touch events and scrolls clear a pending tap, so the release of a modifier after a scroll no longer counts.

Login and sessions

The unlock dialog is centered through a bin layout sized to the monitor and the available height, which handles the on screen keyboard case more cleanly than the old preferred size calculation. The user image is hidden when it is the default, and the widget is re centered on each use of the screensaver.

Libraries and build

The i18n script now reads the installed config.py instead of the source copy, and the generated .desktop files were refreshed. The meson project version moves from 6.8.3 to 6.8.4. No library APIs changed in this release.

Known regressions and deferred work

None listed yet. The default avatar hiding applies to the screensaver, the menu applet and the user applet popup, but the panel icon was deliberately left alone. The translation refresh changes strings and keywords across the desktop files only.

Sources

The authoritative change list is the 6.8.4 Debian changelog, with the full 6.8.3 to 6.8.4 diff and the tagged source tree. The modal dialog fix is discussed in a pull request and landed in that fix. The workspace switch fix is a pull request, which closes an older report. The screensaver, avatar and i18n details come from the tagged diff of the user widget code and screen shield code.
