Flatpak 1.19: what actually changed

Flatpak 1.19.0

Flatpak 1.19 ships as a beta development release, dominated by nine security fixes and a polkit-authenticated path for system-wide downgrades.

Flatpak 1.19.0 was released August 11 as a development/beta release (the final 1.19 is not yet timed). The headline is security-driven: nine CVEs were resolved, ranging from a full sandbox escape to integer overflows, and the system helper gained polkit-authenticated downgrades so administrators no longer need root to downgrade system apps.

This is a beta. Nine security fixes and the bug-fix batch are already published; the new features are landed and stable API-wise, but the release is not yet declared stable.

Things worth your attention

Security

Flatpak 1.19 resolves nine security advisories. A representative subset:

  • Sandbox escape with full host filesystem read/write via symlink attack on app data directories ([GHSA-8688-9x26-hhxj]).
  • Local root privilege escalation via revokefs symlink path traversal and commit tampering ([GHSA-qrwq-7qwx-q9rp]).
  • Arbitrary root write via symlink and path traversal in extra-data extraction ([GHSA-fqx6-vh4p-42cg]).
  • Arbitrary root write via path traversal in flatpak build-init ([GHSA-8qxj-x646-phcm]).
  • Arbitrary host file read via hardlink path traversal in OCI archive extraction ([GHSA-9rww-v4mm-x4jg]).
  • Path traversal via unvalidated architecture parameter in DeployAppstream ([GHSA-v2gw-v9h5-9q4x]).
  • Buffer overflow in OCI delta stream path names on 32-bit systems ([GHSA-jr92-2v97-wgvc]).
  • Fixed-filename writes to arbitrary locations via symlink attack on .ld.so ([GHSA-99wv-m8rp-g58x]).
  • Extension metadata path traversal allowing host filesystem probing ([GHSA-w69g-9x8j-7p8f]).
  • Anti-downgrade bypass allowing unprivileged users to downgrade system apps ([GHSA-q4gr-vc25-57m5]).

All of these affect distributors and system administrators who package or deploy Flatpak at scale. End users benefit automatically once their distro updates the flatpak package, but the downgrade bypass is particularly worth flagging: it was exploitable by any local unprivileged user on multi-user systems.

Downgrades authenticated via polkit

The system helper can now perform system-wide downgrades authenticated through new polkit actions instead of requiring root ([#6669]). This replaces the previous behavior where downgrading a system-installed app needed root privileges. Who it affects: distribution integrators, fleet managers, and developers who need to pin or roll back system apps without granting full root access.

Coredump inspection

Added flatpak-coredumpctl list subcommand alongside Bash completion for flatpak-coredumpctl ([#6705], [#6678], [#6677]). Developers debugging application crashes inside sandboxes can now enumerate coredumps without leaving the flatpak tooling.

Smaller changes

Performance and internals

  • Added flatpak_transaction_progress_get_bytes_per_second() to the library API ([#6679]), so tooling can display real-time download/progress rates.
  • The session helper’s runtime directory is now locked to prevent systemd-tmpfiles from cleaning the p11-kit socket ([#6754]).
  • OCI signatures are now checked from the mirrored repo in the system helper rather than fetched from the lookaside server ([#6682]), improving reliability in air-gapped or offline-mirror setups.
  • Translation updates shipped for pt_BR ([#6701], [#6751]), sl ([#6726]), sv ([#6750]), uk ([#6715]), and zh_CN ([#6748]).

Developer tools

  • Bash completion cleanup ([#6710]) makes the shell hints consistent across install/update/override subcommands.

Bug fixes

Sandbox, build, and portal integration

  • Fixed the portal flatpak-spawn environment handling regression ([#6721]).
  • --assumeyes no longer sets no_interaction, so credential and polkit prompts still work ([#6744]).
  • The inverted behavior of --clear-env is corrected ([#6722]).
  • Negated permission strings for allow and share run options now parse correctly ([#6684], [#6687]).
  • File forwarding of empty paths now errors out instead of silently misbehaving ([#6693]).
  • Build failure when exporting metainfo releases.xml files is resolved ([#6698]).
  • Crashes in the portal update monitor ([#6692]) and OCI JSON handling ([#6704]) are fixed.
  • The GI annotation for flatpak_instance_get_all is corrected ([#6696]).
  • TLS certs are now applied to OCI registry requests, and stream write failures propagate to curl ([#6685]).

System helper hardening

  • Remote names are validated, supplementary groups are dropped, and credentials are no longer logged ([#6722], [#6724]).
  • Numerous crash, memory leak, integer overflow, and error-handling fixes across the system helper and core ([#6722], [#6724], [#6723], [#6713], [#6725]).

Known regressions and deferred work

None published yet.

Still in flight

This is 1.19, the development branch. No stable tag has shipped yet (the Flatpak maintainers release a new odd-numbered series roughly yearly, so 1.19 follows the same cadence as past development cycles). A 1.18.x point release line for the stable 1.18 series runs in parallel; the next stable minor (1.20) has not yet entered development. What is missing: the final 1.19.0 stable tag, and any further point releases for 1.18.x that the maintenance branch will accumulate before 1.20 begins.
